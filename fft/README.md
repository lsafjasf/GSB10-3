# FFT 库与卷积（纯 Python 3 标准库）

## 文件
- `fft_lib.py` — 基-2 迭代 Cooley-Tukey FFT/IFFT、自动补零、FFT 卷积、直接卷积参考实现
- `test_fft.py` — 自测（正确性 + 边界用例）、误差数据、耗时基准

## 运行方式
```bash
cd fft
python3 test_fft.py        # 全部自测 + 误差表 + 耗时表，退出码 0 表示通过
```
也可以在代码中 `from fft_lib import fft, ifft, fft_auto, convolve`。

## 补零规则及其影响
- `fft(x)` 要求长度为 2 的幂，否则抛 `ValueError`。
- `fft_auto(x)` 与 `convolve(a, b)` 自动在末尾补零到 `next_pow2`。
- 影响：补零后的 DFT 相当于把原 DFT 在更密的频点网格上求值（频谱插值），
  不增加也不丢失信息，逆变换可精确还原原信号（尾部为零）。
- 卷积时补零到 `N >= len(a)+len(b)-1`，使圆周卷积等于线性卷积，
  取前 `len(a)+len(b)-1` 项即为定义上的卷积结果。

## 误差数据（随机均匀输入，max abs error）
| n     | fft→ifft 往返 | FFT 卷积 vs 直接卷积 |
|-------|---------------|----------------------|
| 16    | 1.9e-16       | 8.9e-16              |
| 256   | 4.9e-15       | 1.1e-13              |
| 1024  | 3.4e-14       | 5.4e-13              |
| 4096  | 9.9e-14       | 4.0e-12              |
| 16384 | 4.7e-13       | 1.5e-10              |
| 65536 | 2.1e-12       | 1.3e-09              |

误差随 n 大致按 O(log n)·eps 缓慢增长（每 4 倍长度约 3~4 倍误差），
与 FFT 误差理论上界 O(eps·log n) 一致；直接卷积的 O(n) 次舍入累积反而更大，
因此长序列下 FFT 卷积与"按定义"结果的差主要来自直接法自身的累积误差。

## 耗时数据（本机实测，中位数）
| n      | fft 耗时 (ms) | 每 n·log2(n) 微秒 | 与上一档比值 |
|--------|---------------|--------------------|--------------|
| 256    | 0.105         | 0.051              | -            |
| 1024   | 0.662         | 0.065              | 2.34         |
| 4096   | 3.420         | 0.070              | 2.31         |
| 16384  | 16.202        | 0.071              | 2.26         |
| 65536  | 69.851        | 0.067              | 1.93         |
| 131072 | 200.735       | 0.090              | 2.87         |

长度翻倍时耗时约变为 2.1~2.3 倍，接近理论 O(n log n) 的 2·(1+1/log2n) 倍；
n=131072 处比值偏高（2.87）是内存超出 CPU 缓存后的常数因子增大，
并非复杂度阶的变化。每 n·log2(n) 的归一化耗时基本平稳也印证了这一点。

卷积对比（同长度 n）：
| n    | FFT 卷积 (ms) | 直接卷积 (ms) | 加速比 |
|--------|---------------|---------------|--------|
| 128    | 0.52          | 0.39          | 0.8x   |
| 512    | 1.96          | 7.59          | 3.9x   |
| 1024   | 4.29          | 34.9          | 8.1x   |
| 4096   | 20.8          | 579.8         | 27.9x  |

直接卷积为 O(n²)，长度翻倍耗时约 4 倍；FFT 卷积约 2.2 倍，加速比随 n 线性增长。
小 n（<256）时直接法更快，因为 FFT 有固定开销（三次变换 + 补零）。

## 边界用例（test_fft.py 全覆盖）
- 长度 1：`fft([3.5]) == [3.5]`，`convolve([2],[3]) == [6]`
- 非 2 的幂：`fft` 抛 `ValueError`；`fft_auto` 补零后往返还原，补零尾部为 0
- 全零输入：变换与卷积结果全零
- 极值输入：1e150 / 1e-150 幅值往返相对误差 < 1e-12（本机实测为 0）
- 冲激信号：频谱平坦（|X(k)-1| < 1e-12）
